# Smart Library Management System

A production-ready library management application built with FastAPI, React,
PostgreSQL, SQLAlchemy, Alembic, Docker Compose, and GitHub Actions.

## Features

- JWT authentication with Admin, Librarian, and Member roles
- Book, author, category, copy, issue, return, renewal, and reservation management
- Fine tracking and payment history
- Notifications, scheduled reminders, and email-delivery history
- Audit logs, analytics, dashboards, reports, ratings, and CSV exports
- Database migrations with Alembic
- Backend and frontend health checks
- Automated tests, builds, migration checks, and dependency audits

## Technology Stack

| Layer | Technology |
| --- | --- |
| Backend | Python 3.13, FastAPI, SQLAlchemy, Pydantic |
| Database | PostgreSQL 16, Alembic |
| Authentication | PyJWT, bcrypt, OAuth2 password flow |
| Background jobs | APScheduler |
| Frontend | React, Vite, Nginx |
| Testing | pytest, Vitest |
| Deployment | Docker Compose, Railway |
| CI | GitHub Actions, pip-audit |

## Prerequisites

- Git
- Docker Desktop with Docker Compose
- Node.js 22 and npm for non-Docker frontend development
- Python 3.13 for non-Docker backend development

## Environment Configuration

Copy the safe example file and replace every placeholder with a local value:

```powershell
Copy-Item .\backend\.env.example .\backend\.env.docker
```

Required production settings include:

- `DATABASE_URL`, or the individual `DATABASE_*` variables
- `SECRET_KEY` containing at least 32 random characters
- `ACCESS_TOKEN_EXPIRE_MINUTES`
- `CORS_ORIGINS`
- `TRUSTED_HOSTS`
- SMTP variables when email delivery is enabled

Never commit `.env` or `.env.docker`. Both are excluded by `.gitignore`.

## Run with Docker Compose

From the repository root:

```powershell
docker compose build
docker compose up -d
docker compose ps
```

Default local addresses:

| Service | Address |
| --- | --- |
| Frontend | http://localhost:8081 |
| Backend API | http://localhost:8001 |
| Swagger documentation | http://localhost:8001/docs |
| PostgreSQL host port | localhost:5433 |

Stop the application without deleting database data:

```powershell
docker compose down
```

## Database Migrations

The backend container applies `alembic upgrade head` before starting Uvicorn.
For manual verification:

```powershell
docker compose exec backend alembic current
docker compose exec backend alembic heads
docker compose exec backend alembic check
```

Create a migration after an intentional model change:

```powershell
docker compose exec backend alembic revision --autogenerate -m "describe change"
docker compose exec backend alembic upgrade head
```

Review every autogenerated migration before applying or committing it.

## Tests and Security Audit

Run the backend suite:

```powershell
docker compose exec backend python -m pytest tests -q
```

Run the backend dependency audit:

```powershell
docker compose exec backend pip-audit -r requirements.txt
```

Run frontend tests and build:

```powershell
Set-Location .\frontend
npm ci
npm test
npm run build
Set-Location ..
```

GitHub Actions automatically performs fresh-database migrations, schema drift
checking, dependency auditing, backend tests, frontend tests, and a production
frontend build.

## Health and Readiness

- `GET /health` confirms that the API process is running.
- `GET /ready` executes a database query and returns `503` when the database is
  unavailable.

Local checks:

```powershell
Invoke-RestMethod http://127.0.0.1:8001/health
Invoke-RestMethod http://127.0.0.1:8001/ready
```

Production checks:

```powershell
Invoke-RestMethod https://smartlibrarymanagement-production.up.railway.app/health
Invoke-RestMethod https://smartlibrarymanagement-production.up.railway.app/ready
```

## Security Controls

- Minimum 32-character JWT secret validation
- Configurable token expiration
- Explicit CORS origin allowlist
- Trusted-host validation
- `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, and
  `Permissions-Policy` response headers
- Dependency vulnerability checks using `pip-audit`
- Role-based endpoint authorization
- Password hashing with bcrypt
- Structured operational and exception logging

## Production Deployment

The backend is deployed on Railway. Configure secrets and environment values in
the Railway service settings rather than committing them to Git.

Recommended production values:

```env
ACCESS_TOKEN_EXPIRE_MINUTES=30
CORS_ORIGINS=https://reasonable-growth-production-a6c1.up.railway.app
TRUSTED_HOSTS=smartlibrarymanagement-production.up.railway.app
```

Railway should use `/ready` as the backend health-check path.

## Release Checklist

Before merging a release into `main`, confirm:

- [ ] Working tree is clean and the branch is current with `main`
- [ ] No secrets or environment files are staged
- [ ] Backend tests pass
- [ ] Frontend tests and build pass
- [ ] `alembic current` matches `alembic heads`
- [ ] `alembic check` reports no new upgrade operations
- [ ] `pip-audit` reports no known vulnerabilities
- [ ] Docker services report healthy
- [ ] Local `/health` and `/ready` return success
- [ ] GitHub Actions checks pass
- [ ] Railway deployment succeeds
- [ ] Production `/health` and `/ready` return success
